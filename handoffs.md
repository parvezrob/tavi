## 2026-09-09 (small hours) — #111 P2 merged; the owner's reconnect loop was the app hanging up on itself, not the network

**The finding that mattered.** Device logs (`sudo log collect --device-udid …`, subsystem `com.farfield.tavi`) showed six fresh terminal connections in 90 s on Wi-Fi and more on cellular with **no network event of any kind** — no heartbeat miss, no transport drop, no watchdog cycle. Every one carried `attempt=0` and `resumed=false`, and each was preceded by `grid 125x42 bounds=800x600`. That 800x600 is literally `GhosttyTerminalSurfaceView`'s init frame: a brand-new surface. Chain, proven in a test through the real types: `AgentTerminalView.makeUIView` runs again → `TerminalIOBridge.installTerminal` releases the live renderer → `handleRendererChange(.detached)` drops `resumePoint` (that is `resumed=false`) and pauses (+1 generation) → the install's `.attached` hits `resumeSessionIfReady`, which zeroes `reconnectAttempt` (that is `attempt=0`) and dials (+1). The owner's third generation per event was a second real defect: `pauseSession` had no re-entry guard. Fix: `TerminalSurfaceOwner` keeps the Ghostty surface for the **pane**, so a rebuilt container adopts the surface it already has — generation unchanged, transport untouched, `resumePoint` intact, scrollback kept (the blank screen was the freed surface, and the "freeze" was the redial's repaint). **The trigger — which SwiftUI event rebuilds the container on device — is still unidentified**; `navigationDestination` re-creation is DISPROVED by a passing test, and a probe showed `makeUIView` running once across home redraws, toolbar/title changes, overlays, safe-area changes, sheets, window resize and synthetic keyboard notifications. Leading unverified guess: a cancelled interactive back-swipe. Two fixed-token lines under `terminal.surface` (`container rebuilt; surface kept` / `surface released`) make it readable over the cable; the fix makes every trigger harmless.

**Second real cause, also from the logs.** Scrolling a Claude Code pane emits an SGR mouse report per frame (~60/s, the `terminal-originated control sequence, 10/11/12 bytes` storm). They queued ahead of the heartbeat ping, so `sendTimeout` measured the queue's drain and the phone cycled with `heartbeat-send-stalled`. Fix: the ping leaves out of band (`TerminalOutbound.sendAhead`), wheel reports coalesce into one frame per turn, and only whole validated wheel ticks may be dropped when the queue is deep — never a keystroke, never half a button gesture.

**P2 as planned** also landed: host events heartbeat (15 s ping, terminate on the second miss, chaos-gated, 64 KiB cap); #68 findings 1 and 2 (the 2 s per-socket disk read + hash is gone, one envelope per publisher instead of per socket); phone watchdog 20/35, liveness-based backoff reset, a 15 s first-frame deadline from dial start (this is what makes `hostPause` earn Offline), payload pings and a 2 s handover challenge on both links, `.lost` earning no new Offline, `.restored` named `path-restored`.

**Two things the owner hit live, fixed the same night rather than filed** (owner directive, now in AGENTS.md: *fix what you find*): a slow herdr RPC erased a whole computer from the home — the last list is now held for a 10 s grace, marked with `asOf`, and retried; and `~/.tavi/host.log` held nothing but startup banners, so the computer's side of a drop was unreadable — it now logs socket opened/closed/heartbeat-terminate/revoked/census with a **fixed** reason vocabulary and no peer-supplied text.

**Reviews earned their place again.** Two cold Opus verifiers per package, fold audits, then two GPT-6 Astra seats on the integrated diff found four HIGHs, including two in code written earlier the same night: a failed device-list read left a warm cache usable, and **the lock file I had ordered was worse than the race it closed** — its stale takeover could not prove the owner died, an unreadable lock spun the host forever, and `Atomics.wait` blocked the event loop for 2 s, longer than the phone's whole handover budget. Replaced with optimistic compare-and-swap (stat → read → compute → re-stat before the rename, 3 attempts): no lock, no sleeping, nothing left behind on a crash. Lesson: **an orchestrator's own fix needs a cold seat too.**

**Lessons.** (1) Read the device log before theorising — one `log collect` ended weeks of guessing. (2) The Mac IS the host: four agents running iOS suites in parallel put it at load 169, which made the owner's phone flap and invalidated their testing; the simulator service also spun at 150 % for four hours with nothing running (`killall com.apple.CoreSimulator.CoreSimulatorService`), and Spotlight indexing DerivedData/worktrees was a large share (`.metadata_never_index`).
