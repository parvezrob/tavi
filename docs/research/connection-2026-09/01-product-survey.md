# How best-in-class remote apps connect: facts (research agent, 2026-09-09)

## Remote desktop class
- **Parsec (BUD)**: UDP + DTLS 1.2, custom congestion control; STUN + simultaneous hole punch via WebSocket signal API + UPnP; claims 97 % traversal / 95 % connect. **No public relay** ("never transit Parsec's infrastructure"); Enterprise self-hosted relay only. E2E AES-128-GCM. **No roaming**: 60 s to reconnect "on the same IP address". No iOS client. Rejected WebRTC/WebSockets for latency/NAT reasons.
- **Jump Desktop (Fluid)**: WebRTC (ICE/STUN/TURN); vendor-run global TURN free, nearest server auto; Enterprise self-host = coturn; E2E (DTLS/SRTP, relay can't decrypt); FEC + bandwidth estimation in Fluid 2.0; reconnect not migration. 24 h outage 2023 from message-bus partition (control-plane SPOF). Reviews: "told my Macs are offline… Tailscale makes it much more reliable".
- **Screens (Edovia)**: see 01b. No relay, no punching, port mapping only; tells CGNAT users to install Tailscale.
- **Moonlight/Sunshine**: RTP/UDP + FEC, ENet control; no ICE; UPnP/NAT-PMP/PCP inbound mapping; no relay; VPN is the fallback; App Review 4.2.7a forces LAN-only pairing on iOS; NAT64 bug: IPv4 literal → synthesized IPv6 outside VPN routes (#669).
- **RustDesk**: custom protobuf; hbbs rendezvous + hbbr relay (self-hostable, public default single NY host); own NAT probe; symmetric NAT ⇒ relay; NaCl E2E only if server key configured; **merged WebRTC/ICE 2026-09-05** because "ICE covers a strictly larger connectivity set"; reconnect only; CGNAT bugs (#15920 TCP/UDP different public IPs; #14791 cellular can't reach IPv4-only server).
- **AnyDesk**: TCP-only WAN, server-routed by default, nothing published about traversal; TLS 1.3 + AES-256.
- **Chrome Remote Desktop**: WebRTC for everything (SCTP data channels for input); UDP-only P2P, TURN-over-TCP fallback; Google TURN with bandwidth cap; SPAKE2 PIN + HMAC-signed SDP so Google's signalling can't swap fingerprints. **Only code-level roaming spec in survey**: ICE restart on disconnect, `kCloseAfterDisconnectTimeout = 10 s`, "without needing to re-authenticate"; only the host may restart ICE. Migrated off own protocol because relay reconnects failed for ~5 min on it. PWA, no iOS app.
- **TeamViewer**: outbound-only; "direct in 70 % of cases, rest through router network" (decade-old constant); TLS 1.3; TCP 80 last resort has no auto-reconnect; battery complaints when held open in background.

## Remote terminal / coding-agent class
- **Mosh**: SSP over UDP; roaming by highest-seq authenticated datagram; heartbeat 3 s (learn address, warn user, hold NAT mapping); AES-OCB; no NAT traversal ("forward UDP ports"). Numbers: 3G SSH 503 ms → Mosh 5 ms median; 70 % keystrokes immediate; 0.9 % mispredicted.
- **Blink Shell**: mosh+ssh in-process, **no NetworkExtension** (entitlements verified). Engineered around suspension: background task ≤ min(0.9×remaining, 5 min); serializes sessions with NSKeyedArchiver; **patched mosh-client to dump/reload SSP state** and rehydrate `mosh_main` on resume without new SSH login. `geo track` (100 km accuracy location) keeps process alive for SSH; still "dropped 3 times while composing" (#1122); iOS 26 blank shell on return (#2177); request for Live Activities (#2120).
- **Termius**: SSH/Mosh; auto-reconnect restores tab scrollback not server state; background activity stops "within 20–30 s" on recent iOS (older 2–3 min); workarounds: location, Split View, tmux, Live Activities (shipped 5.6.1).
- **Prompt 3 (Panic)**: SSH + Mosh + Eternal Terminal; roaming delegated to server daemon; "Connection Keeper" = Location Always; jump hosts only for SSH; disabled VPN On Demand by default ("caused instability").
- **Tailscale SSH**: WireGuard/UDP, STUN, birthday-paradox hole punch (>90 % direct), DERP over TCP 443 (HOL blocking) ⇒ Peer Relays over UDP (2025-10). Roaming via outer source IP (whitepaper cites Mosh). magicsock: heartbeatInterval 3 s, trustUDPAddrDuration 6.5 s, endpointsFreshEnough 27 s ("UDP NAT mappings expire ~30 s"). iOS NE 50 MiB jetsam; wireguard-go queues 64 on iOS. **Tunnel surviving background only preserves L3; the app's socket is still suspended.**
- **Eternal Terminal**: TCP 2022; SequenceHeader + CatchupBuffer 64 MB each way; keepalive 5 s client / 11 s server; libsodium secretbox, no rekey/PFS; PR #762: 4 MB disconnect buffer overflow killed sessions → 64 MB + pty backpressure.
- **ttyd/GoTTY/wetty**: WebSocket/TCP; IP change kills session; ttyd SIGHUPs the child on disconnect; GoTTY starts a new process per client. WebKit bug 308073 (iOS 26.3, open): after 10 s background, every new WebSocket hangs in CONNECTING until page reload.
- **Happy Coder**: Socket.IO outbound to slopus relay; zero punching; self-hostable; **only genuine E2E in agent class** (secretbox legacy + AES-256-GCM with DEK wrapped under ephemeral box keypair; QR carries pubkey); metadata unencrypted; resume = per-user monotonic seq + cursor refetch. Bugs: daemon never reconnects with lid closed (#1229); socket silently dies, no liveness probe (#989); mobile misses messages after background (#1308); ~20 h hosted relay degradation (#1682).
- **Claude Code Remote Control**: outbound HTTPS only, registers with Anthropic API and polls; streaming connection; **not E2E, by design**: transcript stored server-side "lets the session reconnect after a network drop"; queues messages/permission prompts while reconnecting; server mode gives up ~10 min offline; presence re-register ~30 min; `--continue` ~4 h; non-permission dialogs expire after 5 min.
- **Codex Remote / Cursor self-hosted / VS Code Tunnels / Codespaces / Omnara**: all long-lived outbound HTTPS/WebSocket to vendor relay, "no inbound ports" as the security feature; VS Code Tunnels put SSH over the tunnel for E2E (only C#/TS SDKs reconnect); Codex Remote: "if that computer sleeps or loses network, remote access stops"; OpenAI guidance for DIY app-server: "use a VPN or mesh networking tool".

## Tunnel-as-a-service
- **Cloudflare Tunnel**: 4 outbound conns on 7844 to two nearby DCs; QUIC preferred (HOL reasons); not E2E (TLS at edge); **unnumbered WS idle timeout** (old 100 s figure removed); "when Cloudflare releases new code … terminates WebSocket connections"; **cloudflared #1652 (open since 2026-05): on QUIC the `Upgrade: websocket` header is dropped; `--protocol=http2` restores it**; ToS names Tunnel public hostnames for large-file traffic.
- **ngrok**: TLS/TCP 443, 8 PoPs, agent redistribution needs consent. **Tailscale Funnel**: only hosted option that can't read traffic (TLS terminates on device); ports 443/8443/10000; unpublished bandwidth limits; #21114 (2026-09, open): Funnel silently stops serving after control-plane reconnect while status reports healthy.
- **zrok/OpenZiti** E2E SDK-to-SDK, 5 GB/day free; **MS dev tunnels** preview, TLS at ingress; **frp** v0.71.0 (2026-08) tcp/kcp/quic/websocket/wss, TLS default, heartbeat 30 s; **rathole** last release 2023-10; **bore** no encryption, no auto-reconnect; **localtunnel** abandoned. Self-hosted single VPS = full geographic RTT.

## Patterns
1. Session lives on the server; client is a re-attaching viewport (mosh-server, etterminal, tmux, Anthropic transcript).
2. Session identity decoupled from the 5-tuple (Mosh seq, WireGuard outer IP, QUIC CID, CRD ICE restart w/o re-auth). Products without it (Parsec, Sunshine, plain WS) drop on handover.
3. Recovery = sequence number + replay buffer, not a fresh connection (ET, Happy, Anthropic queue, Omnara idempotent envelopes). Undersized buffer (ET 4 MB) destroys sessions.
4. Heartbeats converge on 3–5 s (Mosh 3, Tailscale 3, ET 5): detect death, learn new address, hold NAT mapping (~30 s expiry).
5. **Nobody in the coding-agent class hole-punches; everybody in remote-desktop does** (video throughput). For a terminal the bandwidth argument for P2P evaporates.
6. Relay is the reliability floor, not the fallback of shame (TeamViewer 70/30, WebRTC ~15–20 % TURN, Tailscale >90 % direct). Worst reputations = no relay (Moonlight, Screens, Parsec on CGNAT). RustDesk added WebRTC for this.
7. Relay reading traffic buys cross-device resumption (Anthropic); only Happy and Funnel refuse; Happy pays with metadata surface + buggy reconnect.
8. On iOS every terminal vendor uses Location "Always" to keep the process alive; Live Activities is the successor. 20–30 s background on recent iOS; sockets may be reclaimed (TN2277).
9. Blink treats being killed as normal: serialize SSP state, rehydrate on resume.
10. VPN NetworkExtension = separate failure domain with its own 50 MiB budget; even alive it only preserves L3.
11. Control plane is the SPOF that shows as "your machine is offline" (Jump 24 h, Happy 20 h, Funnel silent death).
12. Cellular-specific failures are mostly IPv6/NAT64/CGNAT: invisible on Wi-Fi, large share of "works at home, fails on LTE".
