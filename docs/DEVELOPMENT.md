# Development and verification loop

Practical knowledge for building, deploying, and verifying Tavi end-to-end. Policy lives in [`DEVELOPMENT_PRINCIPLES.md`](./DEVELOPMENT_PRINCIPLES.md); this file is the how.

## How the code is organised

**Host — `apps/host/src/`.**

- Wiring: `index.ts` is the CLI and the process wiring, `config.ts` turns the environment into one `HostConfig`, and `state-file.ts` is the shared atomic read/write for the JSON under `~/.tavi` (its `beforeSwap` hook is the last check before the rename, so a read-modify-write can refuse to swap in a list the file has since moved on from).
- Logging: every module logs through `log.ts` — `log.info/warn/error(component, message, fields?)`, one line per call, `tavi <level> <component>:` in front, info on stdout and warn/error on stderr (the service's log is those two streams). What the CLI prints for the person who typed the command — `doctor`, `pair`, the install checklist, the update result — is not logging and stays on plain `console.log` in `index.ts`, `pair-command.ts`, `bootstrap-deps.ts`, and `package-root.ts`; so does the one line in `runtime.ts`'s launcher template, which runs standalone and can import nothing. `bootstrap.ts` itself prints nothing directly — the checklist goes through `deps.report`, and `bootstrap-deps.ts`'s `defaultDeps` is where that becomes `console.log`.
- Routes: `server.ts` holds the process's own wiring — auth, shutdown, the two `WebSocketServer`s (events and terminal) and their `connection` handling, the one `AttachmentStore`, and the defaults for every injectable in `TaviServerOptions` — plus an ordered dispatcher over `routes/` — `health`, `pairing`, `devices`, `host`, `agents`, `herdr`, `files`, `source-control`, `preview` (#91) — with `websocket-upgrades.ts` holding the two WebSocket upgrades (the events stream and one pane's terminal), `http.ts` holding the `RouteContext` a route is handed, `auth.ts` the bearer check, `validation.ts` the pane-id and parameter rules, `protocol.ts` the v2 frame codec, and `types.ts` the shapes the whole process shares.
- herdr: reached only through `herdr.ts` (the agent methods) and `herdr-events.ts` (the event feed and the Terminal hand-back) — `herdr-types.ts` is the contract every consumer imports, `herdr-rpc.ts` the one socket call per request, `herdr-tabs.ts` the tab and workspace tree — with `agent-kinds.ts` for the launchable kinds, `dialog.ts` for reading a permission dialog off a pane, and `attention.ts` + `claude-hooks.ts` + `claude-hook-relay.ts` for needs-you truth from Claude Code's own hooks.
- Terminals: `attachment.ts` (the durable pty, its ring buffer, the detach grace) and `terminal-bridge.ts` (WebSocket ↔ pty).
- Events socket, and what an idle phone costs (#111, #68): `socket-heartbeat.ts` is `keepAlive`, wired only into the events stream — a ping every 15 s, a terminate after two unanswered ones, the timer unref'd and cleared on close, and pings routed through the chaos gate so a blackholed socket is neither pinged nor counted; its clock and its ping's send completion are seams, which is how a 45 s terminate and a send that never returns are tested without waiting. Two costs a paired phone used to pay while doing nothing went with it: `DeviceRegistry` answers the 2 s credential recheck from an in-memory list instead of reading, parsing and hashing `devices.json` once per socket per 2 s. Every check stats the file (mtime, size and inode, since two writes can share an mtime); the list is re-read when that changed, after every write this host makes, and at least every 30 s regardless — so `tavi devices revoke` from another process lands within one recheck, no qualification. A failed read is never cached (one transient EIO would otherwise lock every phone out) and never used to compute a write (appending to it would drop every device the file holds). Two things make the cross-process read-modify-write safe rather than merely narrow: last-seen moved out of `devices.json` into `devices-seen.json`, so no read path writes the list at all, and `add`/`revoke` — the only writers left, in whichever process — hold `devices.json.lock` across read, mutate and rename. Both of those files are `devices-file.ts`'s: `withDeviceListLock` (`openSync` `wx`, pid and timestamp inside, ~2 s of short waits, a lock over 10 s treated as stale and taken over, released in a `finally`) and `readLastSeen`/`writeLastSeen`. Read paths never take the lock. A writer that ignores the lock is still caught by the swap check `writeStateFile`'s `beforeSwap` gives it: the rename is abandoned and the whole read-modify-write retried, up to three times. The `{type:"agents",…}` envelope is serialized once per publisher, never once per socket — `herdr-events.ts` builds one as its own change detector, `attention.ts` holds a single inner subscription and builds one more after merging, and every phone is handed that same text.
- Disk: `files.ts`, `changes.ts`, and the git family over its one runner `git-exec.ts` — `git.ts` (the repository/worktree listing behind `/api/repos` and its cache), `git-refs.ts` (branch, base, upstream and ahead/behind facts, one git read each), `pull-request-cache.ts` (the `gh` badge lookup and its LRU), `gh.ts`, `source-control.ts` (Changes), `commits.ts` (Commits: log, push, pull-base), `commit-message.ts` (the `claude` CLI writer), `pull-requests.ts`, `worktrees.ts` (create), `removal-preview.ts` and `removal.ts` (the two steps of removing one), `removal-sweep.ts`, `uploads.ts`, `projects.ts` (recent folders and the roots rule), `workspaces.ts` (the browsable list), and the preview trio `preview.ts` (the ticket registry), `preview-door.ts` (the loopback proxy), `preview-servers.ts` (finding dev servers). `monotonic.ts` is the one clock the caches age against.
- Install and lifecycle: `bootstrap.ts` (the interactive install steps and `BootstrapError`) over `doctor.ts` (the read-only checks), `bootstrap-deps.ts` (the injectable machine actions) and `package-root.ts` (where the durable copy the service runs lives), `pair-command.ts`, `command-link.ts`, `service.ts`, `service-linux.ts`, `herdr-service.ts`, `runtime.ts`, `updater.ts`, `uninstall.ts`, `tailscale.ts`. `testing/config.ts` is the only `HostConfig` fixture.

**Where the tests are.** A module has a sibling `<module>.test.ts` unless a neighbour's suite already drives it end to end: `routes/*`, `http.ts`, `websocket-upgrades.ts`, and `terminal-bridge.ts` through `server.test.ts` / `server.v2.test.ts` (the events socket's own behaviour — heartbeat, frame cap, one shared envelope — through `socket-heartbeat.test.ts`), and each git, preview, or install helper through its owning module's suite (`git-refs.ts` under `git.test.ts`, `commits.ts` under `source-control.test.ts`, `preview-door.ts` under `preview.test.ts`, `doctor.ts` under `bootstrap.test.ts`, and so on). `types.ts` and `herdr-types.ts` are type-only. `devices-file.ts` is driven through `pairing.test.ts`. The exception is plumbing with no suite at all — `index.ts`, `pair-command.ts`, `claude-hook-relay.ts`, `herdr-service.ts`, `git-exec.ts`, `log.ts`, `login-shell.ts`, `monotonic.ts`, `state-file.ts`, `pull-request-cache.ts` — and that list is the one to shorten, never lengthen.

**Phone — `apps/ios/Tavi/`.** `TaviApp.swift` is the entry point and `Core/Protocol/HostEndpoint.swift` the one description of a computer's address and credential; everything else is a feature folder. One line per folder, every file in it (kept current by #100):

- `Features/Shared` — what more than one feature needs (#92): `HostClient` (the one HTTP client every `Host…Client` is a route list over), `HostSession`, `Loadable`, `SectionHeader`, `SheetChrome` (`LoadingRow`, `MessageCard`), `TaviTheme` (colour, the two radii, the four-step spacing scale, `taviCard`, `TaviPrimaryButtonStyle`, `FreshnessRule`).
- `Features/Pairing` — `HostPairing`, `PairingPayload`, `PairingScannerView`, `PairingFlowView`, `PairedHost`, `ManageAccessView`.
- `Features/Sessions` — the home. Its state and wire: `HostFleet` (every paired computer), `AgentDirectory` (one per computer), `HostConnection` (the link's published state and its schedule) with `HostConnectionDeadlines` (one dial and every clock that can end it: the connect deadline, the absolute 15 s first-frame deadline, the watchdog) and `HostConnection+Handover` (the 2 s check after a path change, and what a lost or restored path means), `HostEventsSocketing` (the socket seam: `lastFrameAt`, payload pings, pong delivery), `HostReachability` (the "does this computer answer at all?" probe, single-flight and two-misses, #101/#111), `RetryWait` (its redial delay, wakeable), `RecoveryLog` (the last 50 recovery events and the bounded counters per computer, #111), `ConnectionPath`, `HostRoutes`, `AgentWireTypes`, `AgentPreviews`, `AgentPresentation`, `HomeGrouping`, `HomeSections` (what the home draws — the grouping, the chip filter over it, and `HomeLayoutCache`, the memo that runs both only when one of them changed), `HostCredentialStore`, `ProjectPicker`. Its screens: `SessionsView` with `SessionsHomeRows` (glyph tile, needs-you row and section, waiting stack, project agent row), `SessionsHomeCards` (project card, worktree group), `SessionsHomeChips` (the computer strip and its chips), `SessionsHomeHealth` (health label, freshness), `SessionsHomeStateCards` (`StateCard` and the connecting / offline / unavailable / revoked / idle cards over it, plus the last-known banner and the first-run card), `HostTokenForm` (the DEBUG typed host and token), `PermissionDecisionSheet`, and New Agent as `NewAgentSheet` over `NewAgentDraft` with `ComputerPicker`, `NewAgentForm`, `WorktreeForm`.
- `Features/Terminal` — `TerminalSessionController`, `TerminalSessionController+Path` (what the network path is worth to a live terminal: lost ends the session's patience, restored dials now, a change only asks the heartbeat — the 2 s handover check; #111), `TerminalHeartbeat` (one liveness round at a time on an absolute deadline, bounded separately for the queue and for the host's answer; a path change shortens the round in flight rather than replacing it), `TerminalGridSync` (the rendered grid, the last size sent, and the reconcile that closes the gap; #101/#111), `TerminalSessionView`, `TerminalIOBridge`, `TerminalOutbound`, `TerminalComposer`, `TerminalQuickKeys`, `TerminalIdentityHeader`, `ComposerImage`, `JumpToSheet`, `TerminalDevelopmentBootstrap`; `Renderer/` — `AgentTerminalView`, `GhosttyTerminalSurfaceView`, `GhosttyOutputPump` (the grid size, write callback, and feed pump), `GhosttyRuntime`, `GhosttyScreenText`; `Transport/` — `TerminalWebSocketClient`, `NetworkWebSocketTask`, `OnceContinuation` (the receive continuation a state change and a completion race for, first one wins), `NetworkPathObserver`, `NetworkPathWatch` (the monitor task and what changed), `ReconnectPolicy`, `SocketFailure`, `TerminalConnectionState`, `TerminalInputDelivery`, `TerminalProtocol`, `TerminalRecoveryReason`, `TerminalTiming`, `ConnectionTiming` (the timer and clock both features run on); `Dictation/` — `DictationSession`, `SpeechDictationEngine`, `TerminalDictation`.
- `Features/Files` — `HostFilesClient`, `FileModels`, `FilesSheet`, `FileViewerView`.
- `Features/Preview` — `HostPreviewClient`, `PreviewModels`, `PreviewSheet`, `LocalhostPortScanner`.
- `Features/SourceControl` — `HostSourceControlClient` (the route list), `SourceControlWireTypes` (what those routes send), `SourceControlDraft` (everything the sheet holds for one worktree, and every read and write it makes), `SourceControlSheet` (the chrome and the Changes tab), `SourceControlTabs` (the header and the Pull request and Commits tabs, drawing off the draft), `RemoveWorktreeSheet`.
- `Features/Settings` — no client: `AppLockGate`, `SettingsView`, `TerminalFontPreference`, `TerminalFontPreviewView`.

`TaviTests` mirrors that tree with `Fixtures.swift` as its one fixture source; `TaviUITests` holds the owner-run live suites (`TaviUITests`, `TaviScreenshotAudit`, `TaviMemoryChecks`, `TaviChaosSoak` with `TaviChaosSoakReport`, `TaviChaosSoakSupport` and `TaviChaosWire`) over `LiveHostHelpers` (the live host env and the shared pane and terminal helpers).

**Ownership.** The credential: on the host `DeviceRegistry` (`pairing.ts`) is the only thing that mints, stores, or verifies a device credential, and it stores hashes only; on the phone `HostFleet` is the only writer of the paired-host list and of `HostCredentialStore` (Keychain, this device only). herdr: only `herdr-rpc.ts` (for `herdr.ts` and `herdr-tabs.ts`) and `herdr-events.ts` open its socket, the phone never speaks to it, and herdr — not Tavi — is the authority for what panes exist. The pty: `attachment.ts` owns every one, outliving the WebSocket that started it (120 s retention, 8 s detach grace), so `terminal-bridge.ts` only moves frames and closing a socket never ends a pane.

**Security invariants.** Each is enforced in one place; changing the rule means changing that function.

- Nothing outside the configured roots is reachable — `resolveWithinRoots` in `apps/host/src/files.ts` (join against the agent's cwd, `realpath`, *then* containment, in that order).
- Only a paired, unrevoked device gets in — `DeviceRegistry` in `apps/host/src/pairing.ts`.
- A preview reaches exactly one loopback port, for the one device that opened it — `PreviewRegistry` in `apps/host/src/preview.ts` (the door in `preview-door.ts` forwards only what it admits).

## Host

- The host runs as a launchd LaunchAgent `com.farfield.tavi.host` (KeepAlive auto-restart). Logs: `~/.tavi/host.log`.
- **Length gate:** `npm run check:lengths` (`scripts/check-file-lengths.mjs`, run in CI after `npm run lint`) fails on any non-test file under `apps/host/src` over 400 lines and any test over 1500. Its allowlist is empty since #98 split the six known grab-bags, and stays empty: a file over the limit is split, never allowlisted.
- **Deploying host changes:** the service runs `dist/`, not watch mode. From `apps/host`: `npm run build && npm run service:install` (install boots the old instance out, waits for it to actually leave launchd, then bootstraps the new one; a genuine failure prints launchctl's own error — no retry ritual). On SIGTERM the host closes every phone stream with WebSocket code `1001 host restarting` and exits within 2 s, so a deploy with the app open is fine (#21). `npm run dev` remains available for iteration but is not how the phone connects.
- Pair a phone: `npm run pair` in `apps/host` prints a QR (needs the service running and Tailscale Serve up; `-- --url https://…` overrides the detected address). `npm run devices` lists paired phones; `npm run devices revoke <id|name>` cuts one immediately. State: `~/.tavi/devices.json` (credential hashes only) and `~/.tavi/identity.json` (the host fingerprint key).
- Reveal the host's own token: `npm run token` in `apps/host` — the CLI/dev credential, never handed to a phone once pairing is in use.
- The launchd plist sets a UTF-8 `LANG` deliberately: launchd provides no locale, and agents, the pty bridge, and herdr's NDJSON all assume UTF-8.
- Host tests: `npm test` in `apps/host`.
- **Herdr contract test (#69):** `apps/host/src/herdr.contract.test.ts` asks a real herdr whether it still honours what `herdr.ts` assumes — the protocol ≥ 17 and `agent.list` shape gate, a pane reported as a Terminal and released again, `agent.send_keys` refused on a pane seconds old, a tab rename reaching the agent list, and `--takeover` attaching over a client herdr still has registered. It is skipped unless `TAVI_LIVE_HERDR=1`, and creates its tabs in a temp folder and closes them in teardown. After a herdr upgrade, with the owner off the phone: `cd apps/host && TAVI_LIVE_HERDR=1 node --import tsx --test src/herdr.contract.test.ts`. A failure here is the herdr note in [`HERDR_INTEGRATION.md`](./HERDR_INTEGRATION.md) going stale, not a Tavi bug.
- **HTTP routes (#91):** every documented route section of [`../protocol/README.md`](../protocol/README.md) lives in exactly one file under `apps/host/src/routes/`, and a file may hold several sections; the off-name placements are `GET /api/host` and `POST /api/update` in `host.ts`, `GET /api/projects` and `POST /api/hooks/claude` in `agents.ts`, `GET /api/changes` and `GET /api/changes/file` in `files.ts`, and `GET /api/repos` and `GET /api/repos/issues` in `source-control.ts`.
- **Tester install path (#47):** the host is the npm package `tavi-host` (bin `tavi`, published from `apps/host`). `tavi pair` runs `bootstrap()` first (`src/bootstrap.ts`, over the checks in `src/doctor.ts`): one checklist (✓ what is fine, • what will be done), **one** yes/no question, then a ✓ line per step — owner direction 2026-09-01: the command resolves as it goes, nobody goes looking for downloads, and nothing technical (systemctl, launchctl, serve flags) reaches the screen unless a step fails, and then it is one plain sentence plus the log path. If the background service cannot start, Tavi is started detached for the session and pairing still completes. The steps: Tailscale missing → `brew install --cask tailscale` / `curl tailscale.com/install.sh | sh`; stopped or signed out → `tailscale up` (prints the sign-in link; Linux first makes the user an operator with `sudo tailscale set --operator=$USER`); Serve denied → the operator question; HTTPS certs off → the admin-console link and a retry; service missing → launchd (macOS) or systemd user unit (Linux, `src/service-linux.ts`, #48) and a wait on `/api/health`; herdr missing → offered, never required (tmux is not a dependency of anything since #53). Non-interactive runs answer no and end with `doctor`'s instructions; `--yes` answers yes. `deps.run` inherits the terminal so sudo prompts and sign-in links reach the person; `deps.execute` is the quiet variant for status checks. `tavi doctor` prints the same checks read-only (`src/doctor.ts`). Under `npx` the package lives in npm's cache, so `durablePackageRoot()` installs a permanent copy into the **managed runtime** and the service runs it through a launcher; a checkout or `npm i -g` is used in place and never self-updates. `TAVI_PACKAGE_SPEC=<path.tgz>` overrides what that durable copy is installed from — how to test an unpublished build end to end: `cd apps/host && npm pack`, then `npm install --prefix /tmp/_npx/t ./tavi-host-*.tgz` and run `node /tmp/_npx/t/node_modules/tavi-host/dist/index.js doctor` (the `_npx` path segment marks it ephemeral).
- **`tavi` command (#64, 2026-09-02):** an npx install had no command on PATH, so every documented `tavi …` failed and `npx tavi …` ran a stranger's package. `pair` now adds a checklist step that writes a `#!/bin/sh` shim (`src/command-link.ts`) — `exec /usr/bin/env node ~/.tavi/runtime/current/node_modules/tavi-host/dist/index.js "$@"`, so it survives self-updates — into the first of `/opt/homebrew/bin`, `/usr/local/bin` that is on PATH and writable, else `~/.local/bin` with a one-line PATH hint on the ✓ line. `doctor` reports it (only for npx installs; a checkout or `npm i -g` never sees the check), `uninstall` removes only a shim carrying our marker comment.
- **Self-update (owner direction 2026-09-01: nobody re-runs a command for a new version).** Layout, `src/runtime.ts`: `~/.tavi/runtime/launcher.mjs` (stable, written by `durablePackageRoot`, never touched by updates), `current → versions/<v>`, one `npm --prefix versions/<v>` install per version, `pending-update.json` from switch until the new version listens. Updater, `src/updater.ts`: only in the managed runtime (`isManagedRuntime`), 2 min after start and then daily ±10 %, `GET <registry>/tavi-host/latest`, same major only, never prereleases; installs beside the running copy, verifies `dist/index.js --version` prints the new version, writes pending, atomically swaps `current`, prunes to {new, previous}, sends itself SIGTERM — launchd `KeepAlive` / systemd `Restart=always` bring the new copy up. The launcher counts start attempts while pending exists and after 3 failures swaps `current` back to `previous` (real-process test in `runtime.test.ts`). `markStarted` clears pending once the host listens. `POST /api/update` runs a check now; `npx tavi-host update` calls it and waits for the new version's health. `TAVI_AUTO_UPDATE=off` disables; `TAVI_UPDATE_REGISTRY` overrides the check URL (with `npm_config_registry` for the install) — the e2e recipe used 2026-09-01: pack the current build, re-pack it as a fake newer version, serve both from a 40-line local registry that 302s everything else to npmjs, install into a temp `TAVI_STATE_DIR` via `durablePackageRoot` with `TAVI_PACKAGE_SPEC`, run the launcher, `npx tavi-host update`, relaunch, expect the new version and no pending file.
- **Publishing:** `cd apps/host && npm publish` (needs `npm login`; `prepublishOnly` builds and runs the tests; `files` ships `dist/` minus tests plus the node-pty chmod script). Bump `version` in `apps/host/package.json` *and* `VERSION` in `src/config.ts` together — a test asserts they match. node-pty is pinned to **1.2.0-beta.15** because it is the first release with linux-x64/arm64 prebuilds (1.1.0 had darwin/win32 only, so Linux testers needed a C++ toolchain — the first fedora run failed exactly there). Any other platform/arch still compiles with node-gyp; `tavi doctor`'s first check (`Terminal (pty)`) reports a missing module with the distro toolchain command and the `~/.npm/_npx` reinstall, and `server.js` is imported lazily so the CLI can still run to say it. Bump node-pty together with `allowScripts` in the root package.json.
- **Upgrading a host across the rename (Mocha → Tavi, #62):** `npm install && npm run build && npm run service:install` from the repo root. The install boots out the old `com.parvezrob.mocha.host` label and removes its plist; the first start moves `~/.mocha` to `~/.tavi` (pairing kept — no re-pair needed for the host side). Then `npm run hooks:install` so the Claude hook entry points at the rebuilt relay, and rebuild the app. The iOS bundle ID also changed (`com.parvezrob.mocha` → `com.farfield.tavi`), so the phone gets a *new* app with an empty Keychain: delete the old "Mocha" app and pair the new one with `npm run pair`.
- **Chaos mode (#111):** `TAVI_CHAOS=on` starts a host that can inject connection faults on request — `src/chaos.ts` plus `src/routes/chaos.ts` (`POST /api/chaos/fault`, `GET /api/chaos/events`, `GET /api/chaos/attachments`, authenticated like every `/api` route, absent and 404 otherwise). `on` injects nothing by itself: `terminate`, `blackhole ms`, `closeMidOutput code` and `hostPause ms` all come from the routes, and each one logs a `chaos` warn line. `blackhole` pauses the socket and holds every write for the window; a revocation during the window is not held — the gate never covered the `4401` close, but a paused `ws` socket writes that frame and never reads the reply, so without the un-pause both ends would sit on the closing handshake for ws's 30 s timeout — chaos drops the socket's handling and un-pauses it first; `hostPause` withholds every HTTP answer and every upgrade answer for the window and deliberately leaves those sockets to the client's own timeout — a withheld upgrade leaves a socket the host no longer tracks, so a paused host does not shut down cleanly until it is restarted. The boundary is a refusal, exit 2 with one sentence, before anything listens: `NODE_ENV=production`, the managed runtime (`~/.tavi/runtime`), or an `npx` run cannot carry it, so the launchd service (fixed env) never can; a checkout or `npm i -g` may. Owner recipe, beside the real host and never in place of it: `cd apps/host && npm run build`, then `TAVI_PORT=8797 TAVI_PREVIEW_PORT=8798 TAVI_STATE_DIR=~/.tavi-chaos TAVI_CHAOS=on node dist/index.js`; publish it with `tailscale serve --bg --https=9443 http://127.0.0.1:8797` (remove with `tailscale serve --https=9443 off`); its own token is `TAVI_STATE_DIR=~/.tavi-chaos npm run -s token`. herdr is shared, so panes the run creates show up on the real home too.
- Needs-you truth (#22, #60): Claude hooks force `blocked · claude-hook` until `PostToolUse`/`Stop`/`UserPromptSubmit`; because Esc on a dialog fires no hook, `AttentionReconciler` reads the pane's viewport every 3 s while anything is hook-blocked and clears the block after two consecutive reads with no dialog on screen. Hooks apply to new Claude sessions only.

## iOS

- Simulator verification loop (no taps needed):
  1. `xcodebuild -scheme Tavi -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build`
  2. Pick a pane: `GET /api/agents` lists them, or create a shell pane with `POST /api/herdr/tabs` body `{"agent":"shell","cwd":"<abs dir>"}` (returns `paneId`/`tabId`; `DELETE /api/herdr/tabs/{tabId}` closes it).
  3. Launch with the DEBUG bootstrap: `SIMCTL_CHILD_TAVI_DEV_HOST=<https tailscale url> SIMCTL_CHILD_TAVI_DEV_TOKEN=$(npm run -s token) SIMCTL_CHILD_TAVI_DEV_AGENT=<paneId> xcrun simctl launch <sim udid> com.farfield.tavi` — the app opens that pane's terminal straight away.
  4. Inject output by typing in the pane (herdr on the Mac, or the simulator's own keyboard into the surface); verify with `xcrun simctl io <udid> screenshot` and `log show --info --predicate 'subsystem == "com.farfield.tavi"'`.
- Every terminal is a herdr agent pane (#53); there is no other terminal route. `TAVI_DEV_AGENT` is the only way to open one without a tap, and a pane id that does not exist lands on the honest not-attached surface (`terminal.disconnected`).
- `TAVI_DEV_FONT_SIZE=<points>` seeds the terminal font preference at launch (#51). It exists because the preference lives in the app container, which `simctl spawn defaults` cannot reach and cfprefsd caches against direct plist edits. `TAVI_DEV_RESET=1` clears every paired computer and credential, the font size, the viewport record, and the Face ID lock flag.
- **`TAVI_DEV_HOST` must be the Tailscale Serve HTTPS URL.** The app enforces HTTPS + `.ts.net`; `http://127.0.0.1` fails as "Connection failed" and makes every live UI test fail with a misleading "output did not reach the screen".
- Live UI tests need `TEST_RUNNER_TAVI_DEV_HOST/TOKEN` **exported** (CLI assignments to xcodebuild do not reach the runner). The terminal tests create their own shell pane in `knownProjectPath` (`createDisposableShell`), open it through `TAVI_DEV_AGENT` (`launchIntoAgent`), and close the tab in teardown; the streaming tests type their own output loop into that pane (`startOutputLoop`).
- UI-test failure details: `xcrun xcresulttool get test-results tests --path <latest .xcresult under DerivedData/.../Logs/Test>`.
- Physical device install: `xcrun devicectl device install app --device <udid> <DerivedData>/Build/Products/Debug-iphoneos/Tavi.app` — the phone must be unlocked and plugged in; "unavailable" resolves by unlocking and retrying.
- **"App no longer available" on the phone = the development profile expired.** The owner's signing team is a free Apple ID, whose profiles last **7 days**; the app then refuses to launch even though nothing changed. Fix: rebuild with `xcodebuild … -allowProvisioningUpdates build` (mints a fresh profile) and reinstall. Check the current expiry with `security cms -D -i <Tavi.app>/embedded.mobileprovision` → `ExpirationDate`. A paid Apple Developer account (needed for TestFlight anyway) removes the 7-day limit.

- **WebSocket transport is Network.framework, not URLSession (#70, 2026-09-02).** `Transport/NetworkWebSocketTask.swift` (`NWConnection` + `NWProtocolWebSocket`) carries both the terminal (`TerminalWebSocketClient`) and the events stream (`AgentDirectory`). Measured cause: every `URLSessionWebSocketTask` to the same host pinned the previous one through a CFNetwork pre-connect block (~40 KB per terminal open or reconnect, for the app's life; 242 tasks and 2 916 certificates in the heap after 200 trips), while the same cycles on `NWConnection` left nothing behind. Two consequences to know: Network.framework never reports the HTTP status of a rejected upgrade (401/404/400 all arrive as `.waiting(ECONNABORTED)`), so the task reports `handshakeRejected` once and the client asks `GET /api/agents` which permanent failure it was (`TerminalHandshakeProbe`: 401 → revoked, pane missing → gone, anything else → retry); and a connection that would `.waiting` is failed at once — the controller and the directory own retry timing.
- **Terminal recovery (#107, #108):** `TerminalSessionController` owns connection generations, ready deadlines, retry backoff, the resume point and when the session may be live (scene in front, a surface installed); `TerminalHeartbeat` owns the two-bound liveness round; `TerminalIOBridge` issues renderer tokens and answers whether output was accepted. The policy and recovery invariants are authoritative in [PRD §7.13](./PRD.md#713-connection-calm-on-a-bad-link-86-design-2026-09-03-supersedes-the-mechanics-under-78). Controller and events-watchdog regressions use injected transports/timing rather than relying on a failing phone link. Recovery diagnostics use `os.Logger` categories `terminal.connection` and `agents.directory`: fixed reason codes, generation/attempt counters, durations and resume counters only. They add no application log store or export path; retention remains managed by the OS unified log. Credentials, endpoint URLs, private paths, terminal output and remote error descriptions must not enter those records.

Live UI tests need a signed simulator app so the Keychain can retain the seeded host credential. Keep simulator signing enabled (`CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-`); the unsigned setting in `scripts/check.sh` is for the unit-only gate. Carrying it into a live UI run leaves the app unpaired and produces false terminal/typing failures. This uses local ad-hoc signing, not a phone build or provisioning update.

- **Ghostty render path — the embedder drives draws.** In the pinned custom-IO fork (wiedymi/ghostty @ 91fe505), `ghostty_surface_feed_data` updates terminal state but the surface never presents frames on its own in this iOS embedding: the embedder must call `ghostty_surface_refresh` then `ghostty_surface_draw` (safe from any thread). `GhosttyOutputPump` (GhosttyTerminalSurfaceView.swift) owns this — feeds off-main with 4 ms drain batching, refresh+draw at ≤60 fps with a trailing draw, suspended while inactive (background GPU work gets iOS apps killed). This was the root cause of the 2026-08-24 "output frozen until the keyboard moves" bug; any render-path change must preserve embedder-driven draws.
- Simulator gotcha: `simctl spawn <udid> defaults write com.farfield.tavi …` hits the *device-level* domain, which the app never reads. The app's real defaults are the plist under `simctl get_app_container <udid> com.farfield.tavi data` → `Library/Preferences/`.

## Claude Code hooks (needs-you fidelity, issue #22)

- Herdr's `agent_status` is screen detection and can lag or flap around permission dialogs. The host overlays durable facts from Claude Code's own hooks: `PermissionRequest`/`Notification` (permission message) force `blocked` with `authority: "claude-hook"` on the matching agent; `PostToolUse`, `Stop`, or `UserPromptSubmit` clear it (`SubagentStop` deliberately does not). Overlay entries expire after 60 min as a phantom-block backstop.
- Install into `~/.claude/settings.json` with `npm run hooks:install` (merges alongside existing hooks, writes a `.tavi-backup`, safe to re-run; it also replaces the pre-relay curl command). Hooks apply to **new** Claude sessions only. The command is `node dist/claude-hook-relay.js <port>` — the relay reads the token from `~/.tavi/config.json` at fire time and POSTs the hook stdin to `POST /api/hooks/claude`, so the token never appears in any process argv (issue #32). Re-run `hooks:install` after moving the repo (the settings entry carries an absolute path).
- Join key: the hook's `session_id` equals herdr's `agent_session.value` (`sessionRef` on the wire). Agents without a session ref are never overlaid.
- Verified live 2026-08-26: permission ask → `blocked · claude-hook` on `/api/agents` and the events feed within seconds, persists while unanswered, clears on approval via `PostToolUse`.

- herdr's server runs headless: on the owner's Mac it is `brew services start herdr` (launchd, since 2026-09-01, herdr 0.8.2); `tavi pair` starts it as a service where it is missing (`herdr server` under launchd or a systemd user unit). ## Transport quick reference

- Terminal WS: `/api/sessions/{id}/terminal` or `/api/agents/{pane}/terminal`, subprotocol `tavi.v2` (v1 legacy), Bearer token auth. Resume: `?stream=<epoch>&resume=<offset>`. Full spec: [`../protocol/README.md`](../protocol/README.md).
- Agent events WS: `/api/events`, subprotocol `tavi.events.v1` — full agent snapshot on connect and on every change.
- Project picker: `GET /api/projects` (recent folders + root scan + roots); `POST /api/herdr/tabs` requires an absolute existing `cwd` and refuses one outside the roots unless the request confirms with `allowOutsideRoots`. Full shapes: [`../protocol/README.md`](../protocol/README.md).
- Agent kinds the picker offers are detected by the host via the user's **login shell** (`$SHELL -lc 'command -v <kind>'`), cached 60 s — the launchd service has a bare PATH, so plain `which` would miss anything in `~/.local/bin` or a version manager. Catalog: `apps/host/src/agent-kinds.ts` (mirrors `herdr agent start --kind`).
- Project roots come from `TAVI_ROOTS` (comma-separated), defaulting to whichever of `~/Code`, `~/Projects`, `~/Developer`, `~/Documents` exist. They are both the picker's browsable list and the guardrail on where a phone-created agent may start. The host's recent-folder list lives in `~/.tavi/projects.json` (0600) and holds the last 12 folders it launched an agent in.
- Herdr contract and traps: [`HERDR_INTEGRATION.md`](./HERDR_INTEGRATION.md).
